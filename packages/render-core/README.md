# render-core

Deterministic beatmap rendering on WebGPU, with a WebGL2 fallback, MIT OR Apache-2.0. Import from `@vosu-tools/render-core`; parse maps with `@vosu-tools/osu-parse`.

```ts
const map = parseOsu(osuText);
const renderer = await createRenderer({ canvas, width: 1920, height: 1080 });
renderer.setBeatmap(map, {
  mods: [{ acronym: "HR" }],
  scrollSpeed: 20,
  noteSpeed: 1,
  // A replay's results (e.g. from packages/replay's judgeReplay), optional.
  judgements: [{ time: 12200, result: "great", note: 41, object: "circle", x: 256, y: 192, combo: 42 }],
});
renderer.renderAt(12345, {
  cursor: { x: 256, y: 192, pressed: false },
  keys: [false, true, false, false],
});
renderer.destroy();
```

**The tools draw through one pipeline** (`src/playfield.ts`), so Map preview, Skin studio, Practice and Replay renderer cannot drift apart. `createPlayfield({ canvas | device, skin, transparent? })` builds the renderer with Replay renderer's look, the best of the four before: lazer's gameplay defaults under the caller's options (`PLAYFIELD_DEFAULTS`: combo colour normalisation 0.2, the osu! playfield 8 osu! pixels lower as in gameplay; a stable client passes `comboColourNormalisation: 0`), a black screen behind the playfield (`PLAYFIELD_BACKGROUND`, lazer without a map background) and direct presentation (`?presentation=bitmap` in the page URL for headless captures). `playfield.fit(cssWidth, cssHeight)` sizes the canvas with `playfieldSize`: the screen's pixels (ratio capped at 2), supersampled up to 2× until the long side reaches 1920. `loadPlayfieldSkin(resolve, name, { maniaKeys })` loads a file skin over the classic look (`overLook`); built-in looks are drawn once per page (`builtinLook`, never close their bitmaps). Per-tool differences are product ones:

- **Map preview** follows the client: its mods, scroll speed and direction, visual settings, and no combo colour normalisation for stable.
- **Skin studio** draws looping demo maps (three periods, so catch's random offsets follow the loop) with the skin's own combo colours and the client's mania scroll speed and direction.
- **Practice** draws a generated map with the client's mania scroll speed and direction, like Map preview.
- **Replay renderer** draws each track into an offscreen target sized by its layout cell at the export resolution (not `playfieldSize`), cleared transparent for its own background and dim, with the replay's input and simulated judgements. It fits the measured playfield to the cell, so taiko strips and mania stages fill it (stage decorations outside the measured box are cut; the stage stays centred like lazer's).

Map preview, Practice and Skin studio pick the mania scroll speed with `@vosu-tools/client-skin`'s `maniaScroll` (the page's field, the tool's setting, the client's, then lazer's default 8) and divide it by the rate their clock runs at, since both clients keep notes moving at the same real-time speed whatever the rate.

`renderAt` takes **absolute beatmap milliseconds**, before rate scaling. Audio/replay clocks belong to callers. Calls can arrive in any order, including backwards seeks; no accumulated animation state or random frame state exists. `applyMods` returns a copy; DT/HT rate metadata never rescales hit times. The caller scales its playback clock.

`createRenderer({ device, format: 'rgba8unorm', width, height })` borrows a GPU device and does not destroy it. Without `device`, vgpu creates and owns one. Without a canvas, every `renderAt` call must supply `frame.target`, an offscreen RGBA8 target from `renderer.createTarget(width, height)`; `target.read(into?)` resolves with the frame's premultiplied RGBA rows, top to bottom (start reads for several targets before awaiting them), and `renderer.finished()` resolves when the GPU has finished every frame so far. **Default presentation is the canvas's direct swapchain, with no image transfer or CPU readback.** `presentation: 'bitmap'` explicitly selects an OffscreenCanvas swapchain transferred into a visible ImageBitmapRenderingContext, for fallback/capture environments. Pass a fresh canvas when selecting its context type. The preview UI exposes that opt-in as `?presentation=bitmap`; normal launches remain direct. `resize(width,height)` sets output pixel size. Map coordinates are 512×384, centered inside a 640×480 virtual viewport, aspect-preserving; skin stage coordinates can extend into its margins.

**Backends.** `createRenderer` draws with WebGPU and falls back to WebGL2 when WebGPU is unavailable: no `navigator.gpu`, no adapter or device, a device lost while starting, or a failing shader. `backend: 'webgpu' | 'webgl2' | 'auto'` forces one (tests); a given `device` means WebGPU. `renderer.backend` and `renderer.fallbackReason` say which one draws and why; `describeBackend(renderer)` gives the label tools show in their status lines (Map preview's controls badge, Skin studio's preview status, Practice's preview badge, Replay renderer's export line and job `adapter.backend`). Both backends draw the same instances, atlas pages and frame table with the same blending and sampling: WebGL2 runs GLSL ES 3.00 that naga 30 generates from the one WGSL source (`src/shader-glsl.ts`, regenerated with `bun run glsl`, which needs cargo; `test/glsl.test.ts` fails while it is stale). The frame table is an `rgba32float` texture (`FRAME_TABLE_WIDTH` texels per row) because WebGL2 has no storage buffers, and WebGL2 has no base instance, so it re-points the instance attributes per chunk. `tools/map-preview/tests/backend_parity.py` compares the two on every demo map, built-in looks and real skins (tall strips, judgements, input, transparent clear): SSIM ≥ 0.99 (in practice 1.0, except a one-row edge tie on taiko's built-in playfield background, 0.996). `createPlayfield` also survives a device or context lost later: it builds a new renderer the same way on a fresh canvas that replaces the old one in the page, with the same skin, map and size, calls `onRecover(playfield, reason)`, and resolves `lost` only if no backend can draw any more. `tools/map-preview/tests/slider_bodies_e2e.py` checks the slider bodies each backend draws against osu!lazer's, on the GPU and on SwiftShader (`MAP_PREVIEW_RASTERISER=swiftshader`, which every map-preview suite follows), where an interpolated per-instance value once landed just below its integer and drew bodies as another shape: per-instance values reach the fragment stage flat.

`setBeatmap(map, { mods?, ar?, cs?, scrollSpeed?, noteSpeed? })` compiles immutable GPU instance data. `scrollSpeed` is mania's display scroll setting (20 default), with lazer's meaning: notes travel from the stage top to the default hit position in 11485 / `scrollSpeed` ms, whatever the skin's hit position; `noteSpeed` independently multiplies mania/taiko movement. `ar`/`cs` override post-mod values. `setSkin(skin?)` rebuilds the atlas and current scene. Compile and skin changes allocate; normal frames reuse typed arrays, descriptors, submission arrays, and GPU buffers. WebGPU encoders/passes and swapchain views are API-required per-frame handles; transferred ImageBitmaps exist only in explicitly selected bitmap mode. Note/animation data is never rebuilt per frame. Static chunks contain 128 instances with lifetime bounds. WGSL evaluates movement, holds, approaches, visibility, slider-ball interpolation, animation UV selection, pressed key layers, hold bodies and mania texture flips.

`loadSkin(async filename => Blob | null, name?, { rulesets?, maniaKeys?, maxTextureSize? })` accepts an asset resolver. A `SkinScope` (`rulesets`, `maniaKeys`) limits what is requested and decoded: general images only for the rulesets given (0 osu!, 1 taiko, 2 catch, 3 mania; each ruleset's list includes the elements it borrows, such as taiko's swell spinner images and hit* judgement fallbacks, and `test/skin-scope.test.ts` checks the lists against every image a compiled scene asks for), and mania images (the [Mania] paths of every key count and the default `mania-*` / `lighting*` elements; hold bodies can be tens of megabytes each) only for the `maniaKeys` given; omitted fields mean all. A mania 7K scene of a full skin asks for about a tenth of its files. `loadScope(skin, scope)` returns the skin with images for exactly that scope, sharing every bitmap both have, leaving the rest out (the caller closes them once nothing draws the old skin) and never requesting again an image the skin turned out not to have; `sceneScope(map, options)` is the scope a scene draws, `maniaImageNames(skin, keys)` lists what a stage looks up and `maniaKeysFor(map, options)` the key counts a scene draws. Use `/files/skin/<filename>` for the current client skin, or a user-selected folder. It consumes `@vosu-tools/skin-spec`, selects the matching repeated Mania Keys section, and gates known commands against General.Version. An absent INI uses the latest version; an INI without Version uses 1.0. Supported HD skins try @2x first and preserve SD logical dimensions; named subdirectories, explicit @2x paths, and prefixes are retained (mania element paths drop `.png` and `@2x` and use forward slashes, as lazer does). Animated elements use `-0`, `-1`, … (sliderb uses `sliderb0`, `sliderb1`, …) and an immutable GPU UV table. General.AnimationFramerate controls ordinary animations; -1/default completes all frames in one second. Mania elements use lazer's frame lengths (notes 60 fps, hold bodies 30 ms while held, StageLight LightFramePerSecond, lighting `max(1000/60, 170/frames)` ms); slider balls and circle overlays use their fixed-rate exceptions. Missing/corrupt elements fall back independently. Gameplay images keep their full resolution: they are shelf-packed into the pages of one 2D array texture (pages of 4096 px, or `device.limits.maxTextureDimension2D` if smaller; pages widen for wider images and more pages are added rather than shrinking anything). Images taller than a page (mania hold bodies of tens of thousands of pixels) are cut into strips of a page's height, with neighbouring rows copied around each strip so filtering shows no seams; scenes draw one instance per strip and the vertex shader clips each to the image rows it holds, for stretched, repeating and flipped hold bodies alike (`src/atlas.ts`). Only images wider than the device limit are scaled down, with a console warning. Exceeding `maxTextureArrayLayers` throws. `Skin.assets` owns ImageBitmaps; callers may close them after renderer destruction or replacing a skin.

Skin images from files are decoded off the main thread with unpremultiplied alpha, the PNG's own pixels as lazer uploads them. `buildAtlas(sink, skin)` copies each image straight from its bitmap to its place in the texture (`AtlasSink.upload`: `copyExternalImageToTexture` on WebGPU, `texSubImage3D` on WebGL2); only pieces that are edge-padded (wrapped images), scaled down or blank are drawn on a small scratch canvas first, and WebGL2 passes premultiplied bitmaps (the built-in looks) through a canvas so its upload unpremultiplies them. No atlas page is drawn on the CPU. `tools/map-preview/tests/backend_parity.py` compares both backends.

`builtinSkin("legacy" | "triangles" | "argon" | "argon-pro")` returns a normal `Skin` that reimplements a client built-in skin with original Canvas 2D drawings (no textures or code from the clients; see [PROVENANCE.md](PROVENANCE.md)): "legacy" is stable's default skin and lazer's "osu! (classic)". It covers all four rulesets, including per-key-count mania stages with the family's column colours and widths; the classic one also provides the default mania element names (`mania-note1`, `mania-key2D`, …) that skins without their own fall back to. `withFallback(skin, fallback)` layers a file skin over a built-in one the way clients resolve missing elements; bitmaps are shared, so release only the file skin's own bitmaps. `Skin.style` carries traits skin.ini cannot express: the slider body profile (`legacy`, `triangles`, `argon`: radius, border portion, body opacity) and taiko note colours. Skins loaded from files render sliders with the legacy profile (shadow, border, darkened-to-lightened body at 0.7 opacity); unskinned rendering is unchanged. Slider bodies are opaque over the playfield so path segments never double-blend.

`loadHud(files | null)` (`src/hud.ts`) gives a tool lazer's legacy HUD to draw with Canvas 2D: the skin's score and combo fonts (`hud.score`: `ScorePrefix`/`ScoreOverlap`; `hud.combo`: `ComboPrefix`/`ComboOverlap`) and health bar images, decoded by `loadImages` into their own set so they never reach the playfield's GPU atlas (close them with `hud.close()`), over original drawings of the classic skin's (`classicHud`) for anything the skin lacks and for built-in looks. `hudText(font, text, fixedWidth?)`/`drawHudText` lay text out as LegacySpriteText (fixed-width digits for the score counters, proportional for combo) and draw it stretched about an origin, faded, additive or tinted; `rolling`/`rollingAt` are RollingCounter values; `comboChanges` with `legacyComboFrame` (LegacyDefaultComboCounter) or `maniaComboFrame` (LegacyManiaComboCounter) give a combo counter's shown count, stretch and pop-out at any time; `healthFrame`/`drawHealth` are LegacyHealthDisplay with HealthDisplay's initial fill, the frame-eased fill, bulge and flash as pure functions of time. Sizes are lazer UI units (1024×768 minimum-fit). `maniaConfig(skin, keys).comboPosition` is the mania counter's `ComboPosition` in stage units.

Additional `setBeatmap` options, all optional: `beatmapColours: false` uses skin colours instead of the beatmap's combo/slider colours; `maniaScrollUp` mirrors the mania stage for upward scrolling (lazer's ManiaScrollingDirection Up); `snakingIn: false` shows slider bodies fully from fade-in; `snakingOut: false` keeps them whole until the slider ends (lazer's "snaking out sliders"); `hitLighting: false` hides mania lighting. There is deliberately no option that removes scroll velocity changes.

Replay layers are supplied externally: cursor coordinates, per-column key state, judgement events and optional `failed` state. The engine does not grade replay input or infer accuracy. Judgement events (`RenderOptions.judgements`, graded by `packages/replay`) draw lazer's legacy judgements per ruleset: osu! hit/miss pieces, particles and lighting at the object; taiko explosions under the hit target (or judgement pieces for skins without them), with hit notes leaving at their hit and missed ones scrolling on and fading; mania judgements at the skin's ScorePosition and LightingN explosions per hit; catch hit lighting and the legacy combo counter on the catcher, whose idle/kiai/fail state follows the results. Skins lacking an image fall back to the built-in looks. Without events, previews keep autoplay-timed lighting.

A replay's input (`RenderOptions.input`: its decoded frames in map milliseconds) draws what the player did, as lazer does with legacy skins: osu!taiko's input drum halves flash on every press (taiko-drum-inner/outer, positions by skin version); osu!catch's catcher follows the replay, dash and hyper-dash trails are left every 60 Hz frame and an after-image marks each hyper-dash; osu!mania's key images stay down 80 ms after a release and each press lights its column until the release, then the light fades and shrinks over 250 ms; osu! draws the skin's cursor (turning, expanding on presses), cursormiddle and cursortrail (along the path with a cursormiddle, else a part per 1/60 s). Without `input`, previews keep the autoplay catcher and per-frame `keys`. Independently of input: the plate stacks caught objects (lazer's rule with a fixed-seed generator; lazer's own is unseeded) and explodes or drops them when the combo ends; taiko draws the kiai glow (taiko-glow) and, with the top area, the skin's pippidon mascot (idle, kiai and fail frames per beat, clear every 50 combo and completed swell). `playfieldShift: true` moves osu! 8 osu! pixels down, as lazer's gameplay (not its editor) does; off by default. Without external keys, mania previews generate deterministic merged key/hold intervals for pressed receptors and hit lighting. Catch fruits, droplets, tiny droplets and bananas come from `@vosu-tools/ruleset-convert`'s `catchObjects` (lazer's nesting, seeded offsets, Hard Rock offsets and hyper-dash marking); catch previews interpolate an automatic catcher; idle/kiai/fail sprites follow timing-point effects and `frame.failed`.

`parseOsu` preserves General, Metadata, needed Difficulty settings, timing/sample controls (with file order), events/breaks, combo colours, circles/holds/spinners, slider control points and flattened slider paths. Paths are built as lazer builds them (red-anchor segments, linear, Bézier/B-spline, perfect arcs, Catmull, then fitted to the declared length). Mods include HR/EZ/DA, deterministic RD, MR, HD/FI/FL and mania UD. Unsupported lazer mods are not advertised by the preview UI. To show an osu! map as the client plays it in another ruleset, pass it through `convertBeatmap` from `@vosu-tools/ruleset-convert` first.

For instrumentation, `frame.timestampWrites` accepts `GPURenderPassTimestampWrites` (WebGPU only; WebGL2 ignores it); callers must request `timestamp-query` on their borrowed device. Queries measure GPU pass time, not presentation latency. `renderer.textureBytes` is the memory of the skin atlas and its frame table. Headless NVIDIA Chromium works with `--enable-unsafe-webgpu --use-angle=vulkan --enable-features=Vulkan --disable-vulkan-surface`, adding `--disable-gpu-vsync --disable-frame-rate-limit` for pacing experiments. Bitmap mode additionally supports direct canvas screenshots/toDataURL. The first fresh headless adapter request may return null during startup; test harnesses perform a readiness request before initialization.

`parseSkinIni` is exported by `@vosu-tools/osu-parse` and delegates lossless syntax parsing to skin-spec. It exposes every section and repeated Mania block without discarding unknown commands. Skin combo colours and slider border/track overrides are honoured when no beatmap override is present. Taiko uses a horizontal native drum lane with the native 1.4 velocity factor (BPM and inherited SV), finishers, rim/centre notes, rolls, beat lines, and swells; it is not a mania conversion.

Gameplay skin layers include Mania StageLeft/Right/Bottom/Hint/Light, per-key normal/pressed images, note/hold-head/body/tail images, spacing/width/start/hit/light coordinates, KeysUnderNotes, NoteBodyStyle, and normal/hold hit lighting; taiko drum, scrolling background, bar edges, normal/big notes and overlays, rolls and hit position; standard hit circles/overlays, prefixed digit widths and overlap, approach circles, animated slider balls/follow circles/arrows/ticks, skin-coloured tracks and spinner components; catch fruit/drop/banana overlays and catcher states. Taiko and catch scenes follow lazer's legacy layouts (playfield size for the window's aspect ratio, scroller and drum, note and roll pieces, swells, bar lines; fruit pieces, the autoplay catcher with hyper-dash tint), golden-tested against lazer's own drawables (`test/layoutGolden.ts`, `test/reference/VosuLayout.cs`). `RenderOptions.comboColourNormalisation` applies lazer's combo colour normalisation (0-1; lazer's default is 0.2, stable uses 0). Judgement sprites, taiko kiai glow, caught-fruit stacks and catch dash trails are not drawn.

Hold bodies follow lazer's `LegacyBodyPiece`: only the global `NoteBodyStyle` counts (per-column `NoteBodyStyle#` is ignored, as in lazer); Stretch clamps the body image over the hold, every other style stretches it to 32800 units from the tail end with a repeating sampler; tails fall back to the head, then the note image. `loadSkin(resolve, name, { maxTextureSize })` can mark images larger than a given limit in `Skin.blank` (drawn black), to emulate a client whose GPU upload of an oversized texture fails. It is off by default: the limit and what the client then draws depend on its renderer backend and GPU, and no measured value is reported to tools, so oversized images are drawn normally (downscaled in the atlas).

Mania stages are lazer's legacy skinning, ported in `src/mania.ts` from osu! (lazer) 2026.1005.0-lazer (`LegacyManiaSkinDecoder`, `LegacyManiaSkinConfiguration`, `LegacySkin`'s mania lookups, `Stage`, `ColumnFlow`, `Column` and `Skinning/Legacy/*`): the first `[Mania]` block for the key count (lines before its `Keys` included) or lazer's defaults; columns sized by ColumnWidth with half of each ColumnSpacing on either side and the stage centred; column backgrounds (Colour#, alpha applied twice) and ColumnLineWidth lines down to the hit position (right lines from version 2.4, or the last column); StageLeft/StageRight at their own width stretched to the stage height; StageHint scaled (1, 0.9 × 1.6025) and the judgement line (JudgementLine, ColourJudgementLine) centred on HitPosition (clamped 240-480); StageLight column-wide at LightPosition, tinted by ColourLight; keys column-wide at their image's own height on the stage's bottom edge (so receptors drawn for a column width keep their shape), pressed images while held, under the notes with KeysUnderNotes; notes, hold heads and tails column-wide, as tall as their image at WidthForNoteHeightScale (else the narrowest column), with lazer's fallbacks (head → note, tail → head → note, `mania-note{1,2,S}{,H,T,L}` by distance to the stage edge); hold bodies from the middle of the tail to the middle of the head, Stretch over the hold or, for every other NoteBodyStyle (RepeatBottom from version 2.5), the image stretched to 32800 units from the tail, masked at the hit position while held; LightingN/LightingL centred on the hit position at LightingNWidth/LightingLWidth (or the column width) over 48 units, additive; StageBottom at 1.6× on the bottom edge; bar lines (BarlineHeight, ColourBarline) as lazer generates them, fading 150 ms after the hit position. Upscroll mirrors the stage; notes, keys, hint, lights and bodies flip with it, tails flip in downscroll only. Stable differences lazer keeps: the stage is centred (ColumnStart, ColumnRight, SplitStages, SpecialStyle unused), UpsideDown and the flip settings are unused, and repeating bodies stretch instead of tiling. `test/mania.test.ts` compares every element against lazer's own layout (`test/maniaGolden.ts`, `test/reference/VosuManiaLayout.cs`).

osu! spinners, slider balls and follow circles are lazer's legacy pieces (`src/osu.ts`): the old style (background, turning circle, metre, approach circle) or the new style (glow flashing on bonus spins, bottom/top/middle2 turning, middle reddening), picked as lazer picks it from the skin's own images at any skin version; the RPM box and the "spin" and "clear" texts; the ball (`sliderb` frames, `-nd` / `-spec` layers, SliderBall tint and flip) and the follow circle's grow and shrink, with the autoplay spin rate and the playfield shift lazer applies. Images lazer clamps or repeats (taiko drum roll and scroller, mania pieces) get opaque edge padding in the atlas, so filtering never fades their edges. skin.ini values lose trailing `//` comments, as in lazer. Animated elements use their frames whenever a skin has any (a lone `name-0` replaces the plain image, as in lazer's `GetAnimation`); osu!taiko shows autoplay's judgements (with particles) for skins without hit explosions; falling catch objects scroll in from above the playfield like lazer's scrolling container.

For replay composition, `RendererOptions.transparentBackground: true` clears to transparent black; `clearColour: GPUColor` explicitly overrides the clear (including alpha) and takes precedence. Omitted options retain the opaque original background. Transparent output is available in caller-owned offscreen targets; the normal visible canvas remains configured opaque. `FrameState.cursor.scale` multiplies its normal/pressed size (default 1). `cursorTrail` takes caller-owned samples `{ x, y, opacity, scale? }`, oldest first, in the same beatmap coordinate space; up to 511 visible samples are drawn below the live cursor using the existing cursor visual. No history or trail aging is accumulated, so callers control trail duration/opacity and deterministic seeks. `setBeatmap(map, { hitLighting: false })` omits mania stage/normal/hold lighting while preserving key receptors and notes. `noteSpeed` already controls mania/taiko speed independently of playback rate. Existing defaults are unchanged.
