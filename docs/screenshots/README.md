# README screenshots

The README's pictures are real tool pages: the packaged tools, installed from a catalog into an isolated vosu and opened from its dashboard, at 1600×1000 in the dark theme. No osu! client runs, and the pictures contain no third-party content. Everything in them is generated from this repository:

- **Maps**: `18-LAB Demo · osu! tour` and `18-LAB Demo · 7K tour` are periods of [`packages/demo-maps`](../../packages/demo-maps/README.md) repeated at changing tempos. They have no audio or background.
- **Skins**: render-core's built-in looks are original Canvas 2D drawings ([`builtin.ts`](../../packages/render-core/src/builtin.ts)). They are exported as stable skin folders (`18-LAB Demo - classic look`, `- Triangles look`, `- Argon look`), and pages that follow the client's skin get lazer's built-in Argon.
- **Replays**: `Demo A`, `Demo B` and `Demo C` are generated by [`autoplay.ts`](../../tools/replay-renderer/web/test/autoplay.ts), with a deliberate aim error per player.
- **Selected map**: pages that follow the game get the demo map from a stand-in for the game, implemented as Playwright routes: the `/websocket/v2/subscribe` stream in song select, `/json/v2`, the map file and the skin report. These are not live game captures.

## Regenerating

The script runs on Linux. It needs Bun, bubblewrap (`bwrap`, with unprivileged user namespaces), `xz`, Playwright with Chromium, the tool packages from the current commit, and a vosu 1.2.0 or later **debug** build with the `test-harness` feature, which installs from a loopback catalog. vosu refuses that feature in release builds.

```sh
# from a clean checkout of this repository
bun install --frozen-lockfile
python scripts/package.py --target x86_64-unknown-linux-gnu --out "$SCRATCH/packages" \
  --base-url https://example.invalid/releases
# vosu checkout
(cd ../vosu && CARGO_TARGET_DIR="$SCRATCH/vosu-target" cargo build --locked --features test-harness)
# Playwright in its own folder (with its own package.json, so npm does not use a parent one)
mkdir -p "$SCRATCH/playwright" && echo '{"private":true}' > "$SCRATCH/playwright/package.json"
(cd "$SCRATCH/playwright" && npm install playwright@1.64.1 && npx playwright install chromium)

bun scripts/screenshots.mjs --vosu "$SCRATCH/vosu-target/debug/vosu" --packages "$SCRATCH/packages" \
  --playwright-module "$SCRATCH/playwright/node_modules/playwright/index.mjs" --work "$SCRATCH/work"
```

It writes `docs/screenshots/*.webp` (or `--out <dir>`). `--only tools,practice,…` captures a subset, and `--keep` keeps the run folder, with the daemon log, PNG originals and `report.json`.

Isolation: the script re-runs itself inside bubblewrap, with a private network namespace (vosu on 26250/26251 and the browser reach only each other), a `/dev` without GPU devices (Chromium renders with SwiftShader), a private `/tmp`, and no `/run/user`. The run folder is mounted as `/home/player`, which serves as HOME and every XDG directory, so paths in the pictures show that home. Nothing opens on the desktop, and the user's own vosu, settings and osu! folders are never touched.
